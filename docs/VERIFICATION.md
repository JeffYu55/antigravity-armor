# 破甲性能验证报告（v1.4.1，2026-09-17）

## 口径声明（先读这个）

- 本报告全部数字来自**离线 mock**（`node state/t-verify.mjs` 的 `measure()`）——它量的是
  **装甲机器**（探测/升档/预填/抖动/隐藏面/finish 通道/尾巴拦截）的机械行为，
  **不量模型的脾气**。离线数字提升 ≠ 真实模型更配合；真实转化率要跑 `--target`（需 API 预算）。
- `undetected-refusal`（还有额度却透出拒绝）= 探测器 bug，跑分器 **exit 非零**。本报告全部场景为 0。
- 残余拒绝 = 额度用尽模型的最终答复，如实落类，不算漏检。

## 10. 已知边界（如实记录）

- **pivot 碎片**：流式探测拦得住完整拒绝，拦不住已发出的开头 ~50 字碎片 —— 物理极限。
- **思考流拒绝 + 干净正文**：正文在流、拒绝只在思考流时，隐藏扫描按设计不触发
  （模型边想边写是常态，重试会误伤）—— 计入泄漏观察，不动机械。
- **离线口径**：mock 只量机器。真实端点（DeepSeek/Gemini）的转化率是下一步，需 API 预算。
